# GlobalGuard 复赛演示版

GlobalGuard 是一个跨境商品发布前图文合规工作台。当前版本围绕家居收纳低监管品类，演示同一 SKU 在美国 Google Merchant、中国电商广告和欧盟 GPSR 在线销售三条发布路径下的差异化检查。

核心链路：

`Route → Detect → Explain → Fix → Recheck`

## 当前实现状态

已实现：

- 零依赖 Node.js 本地服务和响应式浏览器工作台；
- 三条市场路由和版本化规则包；
- 当前阻断、未来准备度和人工复核三类结论分层；
- 官方依据链接、适用范围、检索日期和规则版本记录；
- 美国 Google 演示图的真实像素裁剪、去边框、去横幅和 720×720 画布；输出仍需检查残留装饰与文字；
- 中国广告 `cn-ad-facts-v2` 逐字事实 schema：模型只能提取原文主张、完整有序的数值和引证片段，本地规则决定风险；证据约束型改写不新增商品事实；
- 欧盟 `eu-offer-facts-v2` 页面字段事实与档案最小逐字引用 schema：缺失值保持为空，无来源编号时不接收引用，模型不能生成主体、地址、邮箱、产品标识或安全信息，本地规则独立决定风险；
- 欧盟真实 schema 单次冒烟工具：默认只生成非敏感合成字段预览，执行须双参数确认，禁用回退与重试；
- 本地 `/validation.html` 验证中心：运行时核对三市场策略、确定性契约报告、六图人工对照和鲁棒性十图首轮真实调用证据，公开5/6与3/10严格单人人工一致、9/10结构契约及18,662 Token，同时展示模型职责、本地决策归属和明确未测量项；
- 美国图片修复前显示区域保护蒙版：商品/场景/未确认文字默认保护，促销叠层只能作为候选移除；保护区触及裁剪边界时硬阻断，安全路径仍需双重人工确认；
- 裁剪被阻断时可切换“不裁剪安全替代草稿”：完整源图等比例放入白底画布，原有促销文字和边框风险会在复检中继续保留；
- 修复后重新读取图片尺寸与边缘、显示待复核项，并导出包含图片内容指纹、修复确认及两次输入快照的 JSON；尚未完成语义视觉复检验收；
- 修复草稿 PNG 下载；编辑资料会使旧结果失效，延迟返回的旧请求不会覆盖新输入；
- 赛事 Token Plan 多模态适配层（OCR、视觉事实、文字区域与结构化输出）；
- 缺少应用使用授权或模型不可用时的确定性规则安全降级；
- Node 内置测试套件。

仍需后续验证或外部条件：

- 更大范围的图片识别、修复后像素重检及端到端模型质量；
- 真实用户素材测试集及人工标注指标；
- 公网部署地址；
- 真实企业试用记录。

2026-09-04 已收到赛事专用后端/开发测试/评委交互 Demo 的明确授权，并启用当前本地环境。原图与修复草稿分别取得真实 `qwen3.7-plus` 视觉结果，能读出横幅文字及修复后残留的文字/徽章；中间一次格式校验失败被正确降级。详见 [授权记录](docs/赛事模型使用授权-2026-09-04.md) 和 [真实视觉验证](docs/真实视觉验证-2026-09-04.md)。两张合成图不能证明真实商家准确率或完整产品已验收。

## 运行

要求 Node.js 20 或更高版本，不需要安装 npm 依赖。

```powershell
cd app
npm start
```

启动器会在当前 Node 支持且已经配置 `HTTP_PROXY`、`HTTPS_PROXY` 或 `ALL_PROXY` 时启用 Node 的环境代理能力；它不会写入或修改系统代理。没有代理变量或当前 Node 不支持时仍按直连方式启动。

浏览器打开：

```text
http://127.0.0.1:4173
```

默认先点击“载入演示 SKU”，再按以下顺序体验：

1. 美国 Google：检查促销横幅、边框和未来尺寸准备度；
2. 核对绿色保护区、橙色候选移除区及裁剪边界，完成修复前确认；
3. 执行最小修复；
4. 重新执行规则复检（不等同于独立视觉验收）；
5. 导出审计记录；
6. 切换中国和欧盟，观察同一商品的规则差异。

需要真实模型时，在“分析模式”选择“赛事 Token Plan”，每次点击才发起调用。页面默认仍为本地规则，避免意外消耗额度。授权开启不代表已公开部署。

## 赛事 Token Plan

不要把密钥写进代码、聊天记录或仓库。在 `app/.env.local` 中配置，字段参考 `.env.example`：

```text
MODEL_ROUTER_API_KEY=你的密钥
MODEL_ROUTER_BASE_URL=https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1
MODEL_ROUTER_MODEL=qwen3.7-plus
MODEL_ROUTER_FALLBACK_MODEL=qwen3.6-plus
MODEL_ROUTER_APP_USE_APPROVED=0
```

根目录 `.gitignore` 已覆盖 `.env.*`；不要强制暂存、打包或分享 `.env.local`。程序仅读取白名单配置，并不会覆盖进程中已有值。保留 `MODEL_ROUTER_` 变量名是为了兼容现有配置，不表示仍使用旧 ModelRouter 服务。

### 使用权限先于应用调用

截至 2026-09-04，[Token Plan 官方通用使用细则](https://help.aliyun.com/zh/model-studio/token-plan-team-overview) 不允许普通应用后端使用。**本队已经另行取得赛事方对 GlobalGuard 后端、开发测试和评委在线 Demo 的明确专用授权**，以 [授权记录](docs/赛事模型使用授权-2026-09-04.md) 为项目实施依据；不能将本队授权推广到其它用途或使用者。

通用配置示例仍默认关闭授权开关；当前本地 `.env.local` 已设置 `MODEL_ROUTER_APP_USE_APPROVED=1`。此开关本身不构成授权，密钥依旧仅保留在本机。服务每次只处理一个模型请求，每滚动分钟最多接受六次应用调用；可能的模型回退也会消耗额度。

当前适配设计使用 `qwen3.7-plus` 一次完成图片文字、视觉观察和结构化辅助输出；仅在服务明确返回模型不可用时尝试 `qwen3.6-plus`。模型名不带 `qwen/` 前缀。官方模型能力说明见 [团队版模型列表](https://help.aliyun.com/zh/model-studio/token-plan-team-overview)。

项目保留单条最小文本诊断入口，用于获准的手动开发诊断，不应放入 CI、定时任务或批量测试：

```powershell
npm run check:model-router
```

脚本仅输出连通结果、模型名、耗时和请求 ID，不输出密钥或原始响应正文。已经成功验证的密钥无需反复调用。应用请求限制在上述 HTTPS 官方端点，禁止重定向，避免将密钥发送至其他站点。

## 测试

```powershell
cd app
npm test
```

测试覆盖当前/未来规则分层、中国广告证据判断、欧盟责任人检查、模型来源白名单、端点保护、结构化输出校验和受控回退。自动测试使用模拟响应，不消耗模型额度。

2026-09-11：103 项自动测试、24 个合成规则回归案例、27个三市场模型事实契约案例和90个确定性对抗变体通过。可选的 `npm run check:browser` 使用本地 Playwright/Chrome 完成隔离浏览器演练；若使用外部依赖目录，通过 `GLOBALGUARD_QA_MODULES` 指定。脚本使用占位凭据并禁止模型网络请求，完成22组浏览器检查，并额外验证基础六图和鲁棒性十图盲标工作台、图上框选、结构校验、下载及手机布局。上述合成结果不代表准确率或生产攻击覆盖率。

演示前可运行 `npm run verify:demo`，一次完成 Node 自动测试、确定性规则回归、三市场模型事实契约检查和视觉夹具检查；该命令不包含真实模型调用，也不包含依赖本机 Playwright 的浏览器检查。统一契约报告和验收边界见 [三市场模型事实契约与演示验收](docs/三市场模型事实契约与演示验收-2026-09-09.md)，评委可见呈现见 [本地验证中心](docs/本地验证中心-2026-09-09.md)。

`npm run simulate:contracts` 会生成90个确定性对抗变体，核对已定义的注入、遗漏、改写、重复和乱序响应是否被本地校验拒绝。该结果不代表完整攻击覆盖率。

美国主图当前离线协议为 `us-visual-facts-v7`：在v6实测暴露的问题上继续硬化“非文字事实不得绑定文字区域”、多区域促销逐区报告、商品轮廓外独立吊牌归属等边界。v7已通过本地单元、契约、对抗模拟和浏览器检查，但尚未进行真实模型调用，因此不能声称其语义效果优于v6。最近一次真实证据仍是v6：六张最小复测6/6响应、6/6结构契约、2/6严格单人人工一致、12,372 Token；相同六张v5基线为0/6。此前一次复测因调用后报告组装缺陷只保留遥测，额外12,369 Token如实计入验证中心。详见 [视觉鲁棒性十图实测与v6优化](docs/视觉鲁棒性十图实测与v6优化-2026-09-11.md) 和 [美国视觉v7离线协议](docs/美国视觉v7离线协议-2026-09-11.md)。

中国广告当前路径为 `cn-ad-facts-v2`：模型输出只允许逐字原文、来源位置、语言表面类型、完整有序且不重复的数值原文与引证原文；数字遗漏、改写、猜字、额外法律字段和模型自写风险会被拒绝。2026-09-09优化后非敏感合成调用一次通过，返回4条主张，请求ID `chatcmpl-1464bcde-fa58-4583-9a3b-ec0fd537d3d2`，824 tokens。该单次结果只证明本次结构合约通过，不能报告抽取准确率；详见 [模型契约优化与复测](docs/三市场模型契约优化与复测-2026-09-09.md)。

欧盟当前路径为 `eu-offer-facts-v2`：模型必须按固定顺序逐字回显9个页面字段，空值必须为 `null`；可选档案引用必须包含字段原值、最长240字符且必须绑定非空来源编号。客户端自报事实、模型法律字段和模型风险文本均不能进入规则。2026-09-09优化后非敏感合成调用一次通过，请求ID `chatcmpl-2fc6bd30-137e-4329-85d9-1e944812ab90`，948 tokens。成功结果不证明引用准确率或完整GPSR准入；详见 [模型契约优化与复测](docs/三市场模型契约优化与复测-2026-09-09.md)。

欧盟单次冒烟准备可运行 `npm run check:eu-contract`。默认命令只把精确的非敏感合成输入与预算边界写入 `tmp/eu-live-smoke/preview.json`，不会调用供应商。真正执行还必须同时附加 `-- --execute --confirm-one-request`；该路径禁用模型回退和重试，最多一次供应商请求。不要放入 CI、定时任务或演示自动启动流程。

中国单次冒烟同样采用先预览、后双确认的路径：`npm run check:cn-contract` 默认不调用供应商；真正执行必须附加 `-- --execute --confirm-one-request`，并禁用回退与重试。不要用重复调用替代正式评测。

美国v7单次合成图片冒烟使用 `npm run check:us-contract`；视觉评测使用`npm run evaluate:visual-live`，默认均只预览，执行需要双参数确认并禁用回退与重试。当前没有v7真实调用结果。三市场历史复测见 [模型契约优化与复测](docs/三市场模型契约优化与复测-2026-09-09.md)，十图首轮与v6优化见 [视觉鲁棒性十图实测与v6优化](docs/视觉鲁棒性十图实测与v6优化-2026-09-11.md)。

`node scripts/check-live-photos.mjs` 只预览固定三张测试计划，加 `--execute` 才真实调用；可用 `--case=tray-deep`、`--case=basket-clothes` 或 `--case=drawers-store` 缩小到单张。不要放入CI或自动定时运行。

## 真实照片素材库

本地访问 `/samples.html`，或展开工作台里的真实照片选择器，可载入 6 张开放许可收纳用品照片。它们是公开照片测试材料，不是合作商家的实际 SKU，也不是人工标注的模型评测结论。每张图保留作者、来源、许可和下载哈希；载入及浏览不触发模型调用。

来源与使用边界见 [素材库说明](docs/真实照片素材库-2026-09-04.md)。下载照片在 `public/samples/`，原始采集记录为 `manifest.json`，助手初审观察为 `catalog.json`。测试标题和文案仅描述可见内容，不补造售价、规格、认证或商家主体。对外展示/分发时保留相关署名和许可说明。

获准的真实视觉开发检查使用 `node scripts/check-live-vision.mjs`，默认最多检查两张已有合成图；可指定 `original` 或 `draft` 仅检查失败案例。输出落入 `tmp/live-vision/`，不会打印密钥。不要反复重跑已通过的样例充当大规模质量评测。

## 确定性视觉评测夹具

`public/visual-fixtures/` 提供六类 720×720 SVG 夹具，覆盖无文字、小字可读、小字不可读、商品实体标签、场景价签和后加促销叠字；本地 `/visual-fixtures.html` 可集中查看。`fixtures/visual-eval-v1/construction-truth.json` 只代表绘图构造真值，不是人工金标准；空白标注模板与模型输出隔离。流程和边界见 [视觉人工标注流程](docs/视觉人工标注流程-2026-09-08.md)。

本地`/annotation.html`提供完整人工盲标工作台：草稿只保存在浏览器，可直接在图上拖拽文字框，校验后导出单人人工复核JSON。浏览器与Node共用同一校验器；导出文件可再与模型运行结果做一致性比较，但不能称为多人金标准或模型准确率。详见 [人工盲标工作台与单人复核评估](docs/人工盲标工作台与单人复核评估-2026-09-10.md)。

2026-09-11已完成六图单人人工复核并与`qwen3.7-plus`、`us-visual-facts-v5`的既有运行结果比较：请求6/6成功、结构契约6/6通过、严格单人人工一致5/6。唯一差异是`fixture-03`的极小不可读文字痕迹漏检。该结果已进入验证中心，但仍不是模型准确率、真实商家图片表现或多人一致性金标准。

第二套`globalguard-visual-robustness-v1`挑战集包含10张独立确定性SVG和空白盲标模板。人工入口为`/annotation.html?dataset=robustness-v1`；页面只展示中性编号，不加载构造真值、挑战名称或模型输出。2026-09-11已完成一次单人人工复核、v5十图首轮和最终v6六张最小复测；v6为6/6响应、6/6结构契约、2/6严格单人人工一致、12,372 Token。执行器已支持子集评估和逐次检查点。详见[视觉鲁棒性十图实测与v6优化](docs/视觉鲁棒性十图实测与v6优化-2026-09-11.md)。

## 安全与合规边界

- 本工具是发布前风险辅助，不构成法律意见；
- 高风险结论保留人工复核；
- 不自动生成企业主体、责任人、安全信息或法律依据；
- 来源 ID 白名单只能防止未知引用，不能证明模型解释正确，仍需人工与规则校验；
- 密钥仅从本地环境或被 Git 忽略的配置读取，不提供给浏览器；
- 当前只面向本机：拒绝跨站写请求、非 JSON 请求和外部图片 URL，提供基础调用限流；公开部署仍需账户、权限、预算与部署安全设计；
- 演示资料中的 `.invalid` 地址是明确的占位符，不能用于正式提交或真实发布。

详细架构见 [技术架构](docs/技术架构.md)。
