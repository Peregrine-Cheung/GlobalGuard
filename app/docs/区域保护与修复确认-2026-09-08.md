# 区域保护与修复确认（2026-09-08）

## 已实现

- 美国图片路径在生成修复草稿前构建 `us-repair-protection-v1` 计划。
- `product`、`scene`、`uncertain` 文字区域，以及没有绑定促销风险的叠层文字区域，默认进入保护集合。
- 只有与 `GG-US-IMG-004` 或 `GG-US-VISUAL-PROMOTIONAL-OVERLAY` 风险绑定的 `overlay` 区域可列为候选移除。
- 系统把拟保留的裁剪矩形与每个保护区做包含关系检查。保护区只要有一部分位于裁剪矩形之外，就硬阻断自动修复；界面没有勾选绕过入口。
- 可执行路径仍要求操作者分别确认候选移除内容、保护区域与未框出的售卖主体。没有模型区域时会明确显示覆盖缺口，并要求人工检查完整原图。
- 浏览器把确认时间、对应分析 ID、确认范围和完整保护计划写入审计 JSON 1.3。记录仅表示本机界面完成了勾选，不证明操作者身份，也不构成法律审批。
- 若保护区触及裁剪边界，用户可以切换 `safe-reframe-no-crop`。该路径将完整源图作为保留矩形，把所有已观察文字区设为保护区，只生成720×720白底等比例草稿，不执行任何裁剪或文字清除。
- 不裁剪路径使用 `source-content-preserved` 复检语义，原有促销文字、促销状态和边框信号继续进入规则引擎，不能因重新编码或外层白边而被错误清空。

## 当前图像动作

内置演示 SKU 使用已知布局裁剪：源图左、上、右、下分别移除 13、84、13、14 像素，再生成 720×720 白底等比例草稿。用户上传图不会被盲目裁剪，只进行不裁源图的白底等比例排版。无论哪条路径，修复动作都不会直接把语义风险标记为已消除，仍需独立复检。

## 离线验收

- `npm test`：57/57 通过，其中覆盖安全裁剪、商品/未绑定区域误伤硬阻断、无区域覆盖缺口、不裁剪计划的全区域保护和复检风险保留。
- `npm run evaluate`：规则回归单独执行，不把保护门测试冒充规则准确率。
- `scripts/check-browser.mjs`：15 组隔离浏览器检查通过，`pageErrors=[]`；真实模型网络被禁用、凭据为占位值。
- 浏览器链路验证了：绿色保护框、橙色候选移除框、双确认前按钮禁用、商品区域触及裁剪时两个复选框与修复按钮全部禁用、审计包绑定确认记录。
- 浏览器还验证了：从硬阻断切换不裁剪路径后，完整源图像素内容仍在草稿内，复检继续返回 `GG-US-IMG-004` 促销文字和 `GG-US-IMG-003` 边框风险，审计记录 `repairMode=safe-reframe-no-crop`。

## 尚未完成

- 保护区来自已校验的模型文字区域，不等于完整商品主体分割；未框出的无文字商品像素仍依赖人工查看。
- 没有独立人工标注数据，不能报告区域检测准确率、召回率或误伤率。
- 尚未对真实商家图片完成批量清除质量验收，也没有 Google Merchant 实际批准结果。
- 当前只对已知演示布局执行裁剪，不对任意用户图片做生成式擦除或自动裁剪。
