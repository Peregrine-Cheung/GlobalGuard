# OCR 与视觉观察一致性改造（2026-09-08）

## 结论

美国 Google 图片观察策略已从 `us-visual-facts-v1` 升级到 `us-visual-facts-v2`。本轮完成本地结构、校验、审计和界面改造，并对曾出现矛盾的 `basket-clothes` 公开许可照片进行一次受控真实模型复测。单张结果不能证明通用小字识别准确率已经提高。

## 问题来源

2026-09-04 的真实照片复测中，`basket-clothes` 返回 `ocrText=NONE`，但视觉观察同时写到衣物上有可见字符。旧结构只能表达“转写结果”，不能区分“看见文字但读不清”和“本次没有看见文字”，导致同一响应内部含义冲突。

## v2 约束

模型必须返回一个 OCR 状态：

- `readable_text`：存在可可靠转写文字，`ocrText` 必须为实际原文；
- `unreadable_text_seen`：看见文字或字符，但无法可靠转写，`ocrText` 必须为 `NONE`；
- `no_text_seen`：本次没有看见文字迹象，`ocrText` 必须为 `NONE`。

本地校验会拒绝以下响应并进入安全降级：

- 状态与 `ocrText` 冲突；
- `no_text_seen` 与带文字归属的事实冲突；
- `no_text_seen` 与仍提到文字、字符、标签、价签、水印、Logo、标识或品牌的视觉观察冲突；
- 状态缺失、未知、字段类型错误或文本超长。

## 展示与审计

界面不再把所有 `NONE` 统一显示为“未读出”，而是分别显示“看见但无法可靠转写”或“本次未看见文字迹象”；两种结果都保留“不能证明图片没有文字”的提示。

策略版本和 `ocrStatus` 已进入审计记录及输入指纹，指纹版本升至 4。旧 v1 证据文件保持不变，避免把历史真实调用伪装成 v2 结果。

## 验证边界

离线测试覆盖三种合法状态、状态与转写冲突、状态与视觉观察冲突、状态与事实文字归属冲突、前端文案、审计指纹及条件代理启动。43 项自动测试与 24 个合成规则案例均通过；浏览器演示链路完成检测、最小修复与复检，最终保留 1 项人工复核，控制台无错误。

真实复测前发现手动照片脚本启动的临时 Node 子进程没有启用 Node 24 的环境代理支持，即使 `HTTP_PROXY`、`HTTPS_PROXY` 和 `ALL_PROXY` 已指向当前 `127.0.0.1:7897`，请求仍会在传输层直接失败。脚本现仅在当前 Node 支持 `--use-env-proxy` 且存在代理环境变量时为临时服务启用该参数；不修改 Clash 模式、系统代理或持久配置，`NO_PROXY` 仍保证本机回环请求直连。

常规 `npm start` 与 `npm run dev` 也改由 `scripts/start-server.mjs` 启动。启动器使用同一条件判断，确保 README 的正常启动方式能继承现有代理；不保存代理地址，不更改系统设置，旧 Node 或无代理环境会安全回到原来的直连启动。
