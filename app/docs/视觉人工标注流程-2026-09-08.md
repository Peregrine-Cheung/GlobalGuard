# 视觉人工标注流程（2026-09-08）

## 目的

这套夹具用于验证 OCR 状态、文字归属和区域坐标，不把模型自己的回答当成答案。现有公开照片、许可记录和哈希保持不变；新文件全部是项目内确定性生成的 SVG，不冒充真实商家素材。

## 六类夹具

构造集覆盖无文字对照、可可靠转写的小字、不可可靠转写的文字痕迹、商品实体标签、场景实体价签和后加促销叠字。公开资产只使用 `fixture-01.svg` 至 `fixture-06.svg` 的中性编号；具体类别与编号映射只存在于隔离的构造真值中，避免向标注者泄漏答案。

## 数据隔离

- `public/visual-fixtures/` 保存六张可独立查看的 SVG；可通过本地 `/visual-fixtures.html` 打开盲标画廊。
- `fixtures/visual-eval-v1/construction-truth.json` 是生成器根据绘图参数产生的构造真值，只能用于程序验证，不是人工金标准。
- `fixtures/visual-eval-v1/human-annotations.blank.json` 是空白盲标模板，不含构造答案、请求 ID、模型名称或模型输出。
- 正式人工标注时，标注者只查看六张 SVG 和本说明，不打开构造真值，也不查看任何模型响应。
- 画廊、文件名、替代文本和空白模板均只暴露中性夹具编号；若发现类别名称或答案提示，应先停止标注并修复泄漏。
- 完成标注前不得计算或宣传准确率；单人标注应表述为“人工复核标签”，不能冒充多人一致性金标准。

## 标注字段

- `ocrStatus`：`readable_text`、`unreadable_text_seen` 或 `no_text_seen`；
- `ocrText`：能可靠逐字转写时填写原文，否则填 `NONE`；
- `textRegions`：每项记录文字、归属、可读性和归一化 `xywh` 坐标；
- `visualFacts`：只记录允许的可见事实类别及其文字归属；
- `notes`：写明边界不确定性，不写平台处罚推断。

## 生成与校验

```powershell
npm run build:visual-fixtures
npm run check:visual-fixtures
npm test
```

生成器只写入 `public/visual-fixtures/` 的六张 SVG 和 `fixtures/visual-eval-v1/` 的两个 JSON。校验会检查文件哈希、SVG 安全边界、OCR 状态一致性、坐标范围和空白标注模板隔离。
