# 美国视觉六图实测与 v5 优化（2026-09-10）

## 结论

已建立六张确定性合成图片的受控盲跑与计分链路。赛事 Token Plan 的 `qwen3.7-plus` 在最终 `us-visual-facts-v5` 全量复测中取得6/6供应商有效返回、6/6本地结构契约通过、5/6严格构造一致。这里的5/6只描述模型输出与项目合成构造规范的一致性，不是模型准确率、真实商家图片表现、法律正确率或平台审核通过率。

## 本轮新增

- `scripts/evaluate-live-visual-fixtures.mjs`：默认只预览；执行必须同时提供`--execute --confirm-six-requests`，支持`--cases=`缩小范围；逐图最多一次请求，禁用回退和自动重试。
- `src/visual-model-evaluator.mjs`：分别统计供应商是否返回、本地契约是否通过和严格构造一致；小文字定位使用`IoU >= 0.50`或归一化中心距离`<= 0.04`，避免只靠IoU放大小框轻微偏移。
- `tests/visual-model-evaluator.test.mjs`：覆盖完全一致、供应商返回后结构失败、语义差异、定位差异和非法参考集。
- 修正`fixture-05`构造规范：价签中`$19.99`与`STORE TAG`均肉眼可读，两个区域都属于场景实体`scene`。

## v4 基线

- 6次请求均取得请求ID，供应商侧消耗9,760 tokens。
- 4/6通过本地结构契约，2/6严格构造一致。
- 两次安全降级分别来自无文字图中的否定性文字描述，以及不可读笔画图的OCR状态/事实冲突。
- 白色卡片背景出现一次`decorative_border`误报；价签两行文字被模型完整读出，暴露了旧构造规范漏标`STORE TAG`的问题。

## v5 优化

- 明确`no_text_seen`时不写“未见文字”等否定语句，只描述非文字画面事实。
- 明确字符状笔画不可可靠转写时应进入`unreadable_text_seen`，同时禁止把局部小字模糊扩写为整图低清晰度。
- 明确白色卡片、背景色块、商品轮廓、投影和画布边缘不构成装饰边框。
- 明确悬挂、贴靠或连接在商品旁的实体价格牌属于`scene`，并要求价签所有可读小字逐区转写。

针对4个受影响案例的v5检查为4/4供应商返回、4/4结构契约通过，消耗7,276 tokens。最终六图v5复测消耗10,917 tokens，6/6结构契约通过，5/6严格构造一致。

## 保留的能力边界

`fixture-03`由一排极小矩形笔画模拟“看见文字痕迹但无法可靠转写”。最终模型仍返回`no_text_seen`。这是有意保留的可解释漏检案例：产品必须继续把OCR `NONE`解释为“本次未可靠读到”，不能解释为“图片确定没有文字”。不继续针对单一夹具堆叠提示词，以免用过拟合制造满分。

本轮共形成16次有效供应商响应，累计27,953赛事侧tokens；另一次受限网络尝试为6个`fetch failed`，请求ID和token均为0。去敏摘要见`docs/evidence/visual-fixtures-live-v5-2026-09-10.json`，完整原始本地结果保存在`tmp/visual-live-eval/`，不进入提交包。

## 复现命令

```powershell
npm run evaluate:visual-live
npm run evaluate:visual-live -- --execute --confirm-six-requests
npm run evaluate:visual-live -- --execute --confirm-six-requests --cases=fixture-01,fixture-03
```

执行前必须确认输入为非敏感合成素材且赛事授权仍有效。该命令不得放入CI、定时任务或页面自动加载流程。
