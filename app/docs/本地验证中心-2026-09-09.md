# 本地验证中心（2026-09-09）

## 目标

本地验证中心把三市场模型事实契约和一次单人人工复核对照的可信边界直接呈现在工作台中，帮助评委区分“结构校验器按预期工作”“模型与一次人工观察一致”和“真实模型准确率/法律/平台结果已经验证”。入口为 `/validation.html`，主页顶部也提供“验证中心”链接。

## 页面展示

- 当前运行中的美国、中国、欧盟观察策略版本；
- 三条独立事实 schema 各自允许模型返回的内容；
- 本地规则与人工复核仍是决策归属；
- 27个合成契约案例的接受/拒绝结果；
- 六张视觉夹具的模型请求、结构契约、严格单人人工一致结果和逐案例检查；
- `fixture-03`极小不可读文字痕迹漏检及人工复核出口；
- 两份去敏报告的文件路径和 SHA-256；
- 模型准确率、法律正确率、平台审核结果和真实企业试用均明确标记为未测量或未完成。

## 运行机制

`GET /api/validation-center` 在本地读取确定性契约证据和单人人工复核对照证据，同时重新运行当前三市场校验器。只有静态契约报告与当前计算结果完全一致、27个案例全部通过、运行策略版本一致且人工对照报告满足限制字段与计数约束时，页面才显示“结构门禁与人工对照证据已核验”。

接口只返回规则包、观察策略、去敏报告、摘要和边界标记，不返回API Key、环境变量、图片Base64或完整供应商响应。读取页面和接口不会触发真实模型请求，也不会消耗Token。

## 失败处理

- 报告文件缺失、内容损坏或重新计算不一致时，接口失败或页面显示需要核对；
- 策略版本与报告版本不一致时，页面显示版本漂移；
- 页面加载失败时明确显示失败原因，不把错误状态渲染成通过；
- 合成案例绿色状态不转换为模型准确率、法律合规或平台批准表述。

## 实际验收

- `npm test`：99/99；服务端测试验证接口报告27/27、人工对照6案例、摘要与限制字段且不泄露测试凭据；
- `npm run check:browser`：21/21，`pageErrors=[]`；
- 桌面和390px手机视口均无横向溢出；
- 浏览器检查确认3张策略卡、27/27结构案例、六张人工对照卡、5/6严格一致、唯一fixture-03差异、两份64位报告摘要和“模型准确率未测量”同时可见；
- 当前本地服务实测载入三条正确策略，真实模型请求为0。

## 边界

验证中心是本地可信边界展示，不是生产监控、远端证明、数字签名或第三方认证。报告SHA-256只能证明本次本地文件内容的身份，不能证明法规适用性或外部审核结论。5/6只表示模型与一次单人人工复核严格一致，不能写成83.33%模型准确率。
