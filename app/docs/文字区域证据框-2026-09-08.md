# 文字区域证据框（2026-09-08）

## 本轮结果

美国 Google 图片观察策略当前已升级为 `us-visual-facts-v4`。模型在 OCR 三态之外返回文字区域、文字归属、可读性和归一化坐标；v4进一步要求`ocrText`严格等于全部可读区域按序连接结果、拒绝重复bbox，并要求finding显式携带区域ID或`null`。本地校验通过后，区域才能进入风险位置、前端证据框和审计记录。

结构与浏览器链路先在外网被禁止的隔离环境中完成验收，随后只使用 `fixture-06` 确定性合成夹具进行一次真实 `qwen3.7-plus` v3 调用。该单例只能证明当前模型返回的新结构可通过校验并进入坐标链路，不能证明真实图片定位准确率。

## 区域结构

每个区域包含：

- `id`：仅允许 `text-1` 至 `text-8`，同一响应内不得重复；
- `text`：可可靠转写时填写原文，不可可靠转写时必须为 `null`；
- `origin`：`overlay`、`product`、`scene` 或 `uncertain`；
- `readability`：`readable` 或 `unreadable`；
- `bbox`：左上角为原点的归一化 `[x, y, width, height]`，四项均在0到1内，宽高必须大于0且不得越界。

文字类 finding 必须用 `regionId` 引用已验证区域，且 finding 的 `textOrigin` 必须与区域 `origin` 一致。非文字观察不允许绑定文字区域。可读 OCR 必须至少有一个可读区域，`ocrText` 必须包含所有可读区域原文；看见但读不清时至少有一个不可读区域；未看见文字时区域必须为空。

## 信任边界

- 客户端提交的 `ocrStatus`、`ocrText`、`textRegions`、`aiFindings` 和 `observationPolicy` 会被服务端剥离，不能伪装成本次服务端模型观察。
- 越界坐标、猜测的不可读文字、重复/非法 ID、悬空引用、归属冲突或 OCR 三态冲突都会使整次模型输出安全降级。
- 风险标题、规则解释、处理建议和官方来源继续由本地模板产生，模型不能注入这些字段。
- 策略版本、OCR 状态和全部文字区域进入审计记录与输入指纹；指纹版本升至5，浏览器审计导出结构升至1.2。

## 前端显示

- 与风险 finding 绑定的区域显示为橙色框；
- 尚未绑定风险的 OCR 证据区域显示为蓝色虚线框；
- 框的位置先按原图归一化坐标换算，再根据 `object-fit: contain` 的实际显示矩形偏移，避免横图或竖图留白造成错位；
- 坐标和 OCR 都是辅助观察，页面继续提示人工复核，不把证据框当作平台裁定或修复验收。

## 验证

- 52项 Node 自动测试通过；
- 24个合成规则回归通过；
- 隔离 Chrome 完成13组页面检查，外部模型请求被禁止，页面错误为0；
- 浏览器截图确认一个风险绑定区域和一个独立 OCR 区域分别以橙色、蓝色显示，并落在商品图内容区域；
- 服务端安全测试确认客户端伪造的模型观察字段不会进入结果或审计。
- 单次真实夹具调用成功：请求 `chatcmpl-37bba3a4-7756-4396-a7b3-e87e33e74f30`，总计1608 Token，耗时5654 ms；返回 `readable_text`、原文 `SALE 50% OFF`、`overlay` 区域 `[0.08, 0.06, 0.84, 0.15]`，并映射到促销内容风险。
- 与构造框 `[0.0806, 0.0625, 0.8389, 0.1319]` 的单例开发诊断 IoU 为0.8782；高度方向绝对偏差为0.0181。该数字不是模型准确率，也不是独立人工评测。
- 结构化证据见 `docs/evidence/live-fixture-v3-promotional-overlay-2026-09-08.json`，其中不保存密钥或图片 Base64。
