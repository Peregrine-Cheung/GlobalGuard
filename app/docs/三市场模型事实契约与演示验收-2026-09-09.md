# 三市场模型事实契约与演示验收（2026-09-09）

## 结论

GlobalGuard 已建立一套可重复运行的三市场模型事实契约门禁。美国、中国和欧盟使用各自独立的事实 schema，但统一遵循“模型只返回可核对事实，本地规则与人工复核决定风险”的边界。

当前统一合成契约套件共27个案例，27/27通过；另有90个确定性对抗变体全部被拒绝。这只证明本地校验器在这些构造输入上的行为，不代表模型准确率、真实商品合规率、平台通过率、完整攻击覆盖率或法律结论正确率。离线门禁本身没有真实模型调用，Token消耗为0；真实复测另见《三市场模型契约优化与复测》以及去敏证据JSON。

## 三市场契约矩阵

| 路径 | 当前策略 | 模型允许返回 | 本地拒绝重点 | 决策归属 |
|---|---|---|---|---|
| 美国 Google 主图 | `us-visual-facts-v4` | 可见事实、OCR 三态、严格转写、文字区域和区域绑定 | 顶层法律字段、OCR 增删/乱序、重复/悬空区域、把商品实体品牌当水印 | 本地规则 + 人工复核 |
| 中国广告 | `cn-ad-facts-v2` | 标题、文案或可靠图片文字中的逐字主张、完整有序数字和引证 | 改写、猜字、数字遗漏/虚构/重复、模型法律裁定 | 本地规则 + 人工复核 |
| 欧盟 GPSR 要约 | `eu-offer-facts-v2` | 页面已有字段的逐字值、用户档案中的最小连续短引用 | 补全缺失主体、字段乱序、无来源/过长/虚构引用、模型法律裁定 | 本地规则 + 人工复核 |

每条策略包含 2 个应接受案例和 4 个应拒绝案例。美国本轮新增顶层严格白名单，`severity`、`ruleId` 等模型决策字段不再被静默忽略，而是使整次响应安全降级。

## 可重复运行命令

在 `app/` 目录执行：

```powershell
npm run evaluate:contracts
```

该命令生成当前内存报告并打印三条策略的接受/拒绝结果。确定性证据文件为：

`docs/evidence/model-contracts-offline-2026-09-09.json`

检查代码、夹具和证据文件是否同步：

```powershell
npm run check:contracts
```

演示前的一键离线门禁：

```powershell
npm run verify:demo
```

它依次运行92项Node自动测试、24个确定性规则回归案例、27个三市场模型事实契约案例、90个确定性对抗变体和6个视觉构造夹具检查。脚本不访问模型供应商，最终会明确输出`realModelCalls: 0`和各门禁状态。

浏览器验收因依赖本机 Playwright/Chrome，单独运行：

```powershell
$env:GLOBALGUARD_QA_MODULES='<本机Playwright模块目录>'
npm run check:browser
```

## 演示验收清单

演示前只有同时满足下列条件，才能称为“本地演示门禁通过”：

- `npm run verify:demo` 返回零退出码且 `allPassed=true`；
- `npm run check:browser` 返回18项检查且 `pageErrors=[]`；
- `/api/health` 显示三条预期策略版本；
- 演示页面仍明确展示人工复核出口和安全降级，不出现“已获平台批准”等表述；
- 使用演示资料或公开许可照片，不粘贴真实企业敏感档案；
- 如果切换到赛事 Token Plan，必须由操作者明确点击并单独记录真实调用结果，不能把离线夹具冒充真实模型输出。

## 当前边界

- 合成契约案例是结构回归，不是模型质量评测；
- 浏览器中的 live 形状响应由本地拦截夹具提供，不是供应商调用；
- 当前仍缺真实企业样本、独立人工标注和三市场完整法规覆盖；
- 公网部署、真实用户试用和正式法律审核尚未完成。
