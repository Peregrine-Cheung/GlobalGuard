## 一、项目简介

GlobalGuard 是跨境商品发布前的图文合规辅助工作台。针对同一商品在美国 Google Merchant、中国电商广告和欧盟 GPSR 在线销售中的不同发布要求，系统按 `Route → Detect → Explain → Fix → Recheck` 完成市场路由、风险定位、依据解释、最小修复和复检，并保留人工确认与审计记录。

当前复赛版本以家居收纳低监管品类为 MVP 范围。它不是律师、平台审核或产品安全认证的替代品，不承诺“自动合规”。

## 二、可运行产品与体验方式

环境要求：Node.js 20 或更高版本。

```powershell
cd app
npm start
```

浏览器访问：`http://127.0.0.1:4173`

推荐体验顺序：

1. 点击“载入演示 SKU”；
2. 在美国 Google 路径执行本地规则分析；
3. 查看促销叠字、装饰边框、未来尺寸准备度和来源解释；
4. 核对保护区与候选移除区，完成双重人工确认；
5. 执行最小像素修复并重新复检；
6. 切换中国与欧盟路径，观察同一 SKU 的规则差异；
7. 打开 `/validation.html` 查看模型职责、本地规则职责与未测量项。

本地规则模式无需账号。赛事模型模式需要本机私密配置，不随提交包分发；无授权或模型不可用时系统明确降级，不伪造 AI 结果。

## 三、技术架构与模型使用

- 前端：原生 HTML/CSS/JavaScript 响应式工作台。
- 服务端：零第三方运行时依赖的 Node.js 本地服务。
- 决策层：版本化确定性规则包负责风险判断、依据绑定和建议生成。
- 模型层：`qwen3.7-plus` 只负责受 schema 约束的可见或逐字事实提取。
- 安全层：端点白名单、密钥只在服务端、限流、无回退冒烟、结构校验和去敏错误。
- 审计层：记录输入指纹、规则版本、来源、模型遥测、人工确认和复检快照。

三条事实契约：

- 美国 `us-visual-facts-v7`：可见事实、OCR 三态、严格按序转写、文字归属和去重归一化区域；非文字事实错误绑定文字区域时由本地契约硬拒绝；
- 中国 `cn-ad-facts-v2`：标题/文案/可靠 OCR 中可逐字回溯的主张、完整有序数值和引证；
- 欧盟 `eu-offer-facts-v2`：用户已填9字段按序逐字回显与最长240字符的档案最小引用，空值保持 `null`，引用必须绑定来源编号。

模型不生成法律结论、平台通过结论、企业主体、责任人、地址或安全信息；风险由本地规则与人工决定。

## 四、已验证结果

- Node 自动测试：103/103 通过；
- 确定性规则回归：24/24 通过；
- 三市场结构契约：27/27 通过；
- 确定性对抗变体：90/90按预期被拒绝；
- 隔离浏览器流程：22/22 通过；
- 美国v4真实合成调用：3个文字区域和3个事实通过本地schema，本次1628 tokens；
- 中国v2真实合成调用：4条事实通过本地schema，本次824 tokens；
- 欧盟v2真实合成调用：9字段通过本地schema，本次948 tokens；
- 美国v5六图真实受控评测：6/6结构契约通过，与一次单人人工复核严格一致5/6；
- 美国v5鲁棒性十图真实受控评测：10/10供应商响应、9/10结构契约、严格单人人工一致3/10；
- 美国v6六张定向复测：6/6供应商响应、6/6结构契约、严格单人人工一致2/6；同六张v5基线为0/6；
- 美国v7：只完成离线协议与本地校验验收，真实模型调用0，新增模型Token为0；
- 演示视频：离线录制、供应商禁用、62.36秒、1280×720、无配音字幕；已由Chrome实际解码并抽帧核验。

这些结果证明当前代码的确定性行为、结构边界和受控样本表现，不代表真实商品准确率、多人一致性金标准、法律正确率或平台审核通过率。
